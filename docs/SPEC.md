# SPEC.md (Architecture & Requirements Guide)

※ ゲーム名: **Vege-Table**。ドメイン: `vegtab.app`。

## 1. プロジェクト概要

毎日出題されるデイリーパズル（3マッチ）でスコアを競うカジュアルゲーム。Wordleのように「今日の問題」を全プレイヤーが共有し、結果をSNSでシェアする体験を軸とする。

### 1.1. コアコンセプト
- **デイリーパズル:** 毎日UTC 0時に新しいシード（パズル問題）が出題される。全プレイヤーが同じ盤面に挑戦する。
- **シード値固定:** シードごとに初期盤面と落下ピースの順序が完全に一致する。同じシードを何度リトライしても同じ操作で同じ結果が得られる。
- **無制限リトライ:** デイリーシードは何度でもプレイ可能。ベストスコアがランキングに反映される。
- **過去のデイリー:** カレンダーUIで過去のデイリーシードを遡ってプレイできる。
- **4つのゲームモード:** Sprint（手数制限ハイスコア）、Clear（おじゃまタイル除去）、Survival（ウェーブ侵食からの生存）、Cascade（最大連鎖数）。詳細は §3.7。

### 1.2. ランキングとシェア
- ランキングはシードごと・モードごとに存在する。Sprintがメインモード。
- HOME画面からは当日のデイリーシードのSprintランキングにショートカットでアクセスできる。
- プレイ結果はスコアとボードの状態をSNS等にシェアできる。シェア内容にはシード情報・モード・スコアを含む。
- ランキングにはプレイヤーの表示名（display_name）が表示される。
- 自分のランク（順位）がランキングモーダル上部に強調表示される。
- 自分のエントリにリプレイデータがある場合、再生ボタン（▶）が表示され手順再生画面に遷移できる。

### 1.3. ユーザー名（表示名）
- プレイヤーは任意のタイミングで表示名（display_name）を設定・変更できる。
- 最大20文字。未設定の場合は「Anonymous」として表示される。
- ランキングやスコア共有時にこの表示名が使用される。
- HOME画面から設定可能。

### 1.4. 実績（トロフィー）
- パズルプレイを通じて実績を解除できるコレクション要素。報酬なしの純粋なトロフィーシステム。
- 詳細は §3.9。

## 2. UI/UX と世界観テーマ
- **テーマ:** 「野菜」
- **タイル:** 5種類の色の異なる野菜アイコン。視認性を重視し、色だけでなくシルエットでも区別できるデザインとする。
- **アイテム:** 食器・調理器具をモチーフとする。表示名はスプーン（scope）、ハサミ（v_cut/h_cut）、食器セット（burst）、サラダボウル（flush）。詳細は §3.13 のアイテム表示名テーブルを参照。
- **おじゃまタイル:** Clearモードで登場する除去対象の障害物。
- **画面構成:** スマートフォンに最適化。HOMEダッシュボード、パズル画面、カレンダー（過去デイリー）、ランキング。
- **ダークモード:** CSS Custom Properties によるテーマ色定義。`prefers-color-scheme` 自動検出 + 手動トグル。
- **i18n:** 日本語/英語対応。ブラウザ言語自動検出 + 手動切替。
- **アニメーション速度:** パズル画面のマッチ・消去・落下アニメーションの速度を 1x / 2x / 3x / 4x で切替可能。設定メニューから変更。localStorage保存。

## 3. パズルルール詳細

### 3.1. 盤面基本ルール
- **盤面サイズ:** 8×8の正方形
- **タイルの種類:** 5種類の野菜
- **配置決定:** シード値を元にした擬似乱数でタイルの配置と落下順序が決定される。盤面外（下方向）にも無限にタイルが並んでいるものとする。
- **初期盤面:** シード値に基づいてランダム配置した後、マッチが存在する場合は自動消去＋落下を安定状態になるまで繰り返す。この初期自動消去ではスコアは加算されず、アイテムも生成されない。自動消去完了後の盤面がプレイヤーの開始盤面となる。
- **マッチ判定:** 以下の2種類のパターンでマッチが成立し、該当するタイルが消去される。
  - **直線マッチ:** 同種のタイルが縦または横に3つ以上連続で並んでいる場合。
  - **2×2マッチ:** 同種のタイルが縦横2×2の正方形に並んでいる場合。
- **操作:** プレイヤーは隣接するタイルをスワイプで入れ替えられる。ただし、入れ替えの結果マッチが成立する場合のみ有効。
- **落下補充:** タイルが消えた後、上方のタイルが重力で落下し、空いたスペースにはシード値に基づく新しいタイルが上から補充される。落下後にマッチが発生した場合、連鎖として続けて消去される。補充タイルは列ごとに独立した擬似乱数ストリーム（シード値由来）で生成されるため、同じシードであれば各列のN番目の補充タイルは常に同じ色になる（プレイ順序に依存しない決定性）。

  - **列ストリームの独立性（重要）:** 各列のシードは avalanche ハッシュ（`mix32`）で撹拌して生成する。撹拌せずに乱数の生の状態値を列シードに流用すると、列同士が「同じストリームを数ステップずらしただけ」の関係になり、ある列が隣より1回多く補充された時点で状態が完全に一致してしまう。一致した列は以後ずっと同じ色を引くため、盤面が不自然になるうえ、消しても同じ並びが補充され続けて自動消去ループが終わらなくなる。
- **ゲーム終了条件:** ゲームモードにより異なる（詳細は §3.7）。

### 3.2. アイテム生成ルール

ゲーム中に特定のパターンでタイルを消すと、その位置にアイテムが生成される。

| 消去パターン | 生成アイテム | 効果概要 |
|---|---|---|
| 2×2正方形 | スプーン | 周囲縦横4マス消去 + 任意1マス消去 |
| 横4マス直線 | ハサミ(縦) | 縦一列消去 |
| 縦4マス直線 | ハサミ(横) | 横一列消去 |
| 5マス以上連結（非直線） | 食器セット | 周囲2マス消去 |
| 縦または横5マス直線 | サラダボウル | 対象色の全消し |

**独立コンポーネントごとのアイテム生成:** 1回の操作で複数のマッチが発生した場合、色と位置が連結しているマッチ群を1つのコンポーネントとして扱い、**コンポーネントごとに独立してアイテムを生成する**。例えば、スワイプで異なる色の4マッチが2つ同時に成立した場合、ハサミが2つ生成される。同色でも位置が離れていれば別コンポーネントとなる。

**コンポーネント内の優先順位:** 1つのコンポーネント内で複数の生成条件に該当する場合、より上位のアイテムが1つだけ生成される。優先順は サラダボウル > 食器セット > ハサミ(横) = ハサミ(縦) > スプーン。ただし、2×2パターンと3直線マッチが重複した場合はスプーンが成立する。2×2パターンが4直線以上やL/T字型の5マス以上連結と重複した場合は上位アイテムが優先されスプーンは生成されない。

**生成位置:**
- プレイヤーのスワイプ操作に起因する場合 → スワイプ操作の起点位置
- アイテム効果による連鎖消去に起因する場合 → 消去されたタイル群の中央

**連鎖中の遅延配置:**
- プレイヤーの操作で直接発生したマッチ（1連鎖目）ではアイテムが即座に盤面に配置される。
- 2連鎖目以降（落下後のマッチ）で生成条件を満たした場合、アイテムは連鎖完了後にまとめて配置される。連鎖中は盤面に出現せず、マッチや落下に影響しない。
- 連鎖完了後の配置時に同一セルに複数のアイテムが重なる場合、最も優先度の高いアイテムのみが配置される。

### 3.3. アイテム起動ルール

- **起動方法:** タップ（1手消費）またはスワイプで隣接タイルと入れ替え。
- **誘爆:** アイテムの効果範囲内に別のアイテムが存在する場合、そのアイテムも連鎖的に発動する。

**各アイテムの効果:**

| アイテム | タップ / スワイプ起動 | 連鎖発動（他アイテムに巻き込まれた場合） |
|---|---|---|
| スプーン | 1手消費で起動。周囲縦横4マス（上下左右）を消去した後、ユーザーが盤上の任意の1マスを選択して消去する（選択自体は手数を消費しない）。選択したマスがアイテムの場合、そのアイテムを発動する。 | 周囲縦横4マスを消去する（ユーザー選択なし）。 |
| ハサミ(縦) | タップまたはスワイプで縦一列のタイルを全て消去 | 同左 |
| ハサミ(横) | タップまたはスワイプで横一列のタイルを全て消去 | 同左 |
| 食器セット | タップまたはスワイプで周囲2マス分のタイルを消去 | 同左 |
| サラダボウル | スワイプ時：入れ替え先のタイルと同種のタイルを盤上から全て消去。**おじゃまタイルとスワイプした場合は盤上の全おじゃまタイルの耐久値を1減少させる（耐久値0で破壊）。** タップ時：上隣から時計回り順で最初に見つかるタイルと同種のタイルを盤上から全て消去 | 誘爆された時点の盤面状態で時計回り探索を行い対象色を決定する（誘爆元アイテムの消去で周囲が空になる前の状態を使用） |

※ ハサミ(横)のアイコンは、ハサミ(縦)のアイコンを90度回転させたもの。

### 3.4. アイテム合成ルール

アイテム同士をスワイプで入れ替えた場合、特殊な合成効果が発動する。スプーンの合成では、元の位置で周囲縦横4マスの消去効果も追加で発動する。

| 組み合わせ | 効果 |
|---|---|
| スプーン + スプーン | 両方の位置で周囲縦横4マスを消去 + ユーザーが盤上の任意の3マスを選択して消去する |
| スプーン + ハサミ(縦) | スプーンの位置で周囲縦横4マスを消去 + ユーザーが選んだ任意の1マスを起点に縦一列消去 |
| スプーン + ハサミ(横) | スプーンの位置で周囲縦横4マスを消去 + ユーザーが選んだ任意の1マスを起点に横一列消去 |
| スプーン + 食器セット | スプーンの位置で周囲縦横4マスを消去 + ユーザーが選んだ任意の1マスを起点に周囲2マス消去 |
| スプーン + サラダボウル | スプーンの位置で周囲縦横4マスを消去 + サラダボウルの縦横1マス隣から時計回り順で最初に見つかるタイルと同種のタイルを盤上から全て消去 |
| ハサミ + ハサミ（縦横問わず） | スワイプ位置を基準に縦横十字に消去 |
| ハサミ(縦) + 食器セット | 縦3列を消去 |
| ハサミ(横) + 食器セット | 横3列を消去 |
| 食器セット + 食器セット | 周囲3マスを消去 |
| サラダボウル + ハサミ(縦) | 対象色の全タイルそれぞれから縦一列消去が発動 |
| サラダボウル + ハサミ(横) | 対象色の全タイルそれぞれから横一列消去が発動 |
| サラダボウル + 食器セット | 対象色の全タイルそれぞれから周囲2マス消去が発動 |
| サラダボウル + サラダボウル | 盤上のタイルを全て消去。**ただしアイテムは誘爆せず盤上に残留する。** 全消し後、アイテムはその位置に留まり、周囲の空きマスにシード値に基づく新しいタイルが降ってくる。全消しボーナス +1000点。 |

### 3.5. おじゃまタイル（Clear / Survivalモード）

- おじゃまタイルは盤上に配置される障害物である。Clearモードでは初期配置から、Survivalモードではウェーブ侵食（§3.7 Survival）で出現する。
- **耐久値:** Clearでは1〜3、Survivalではウェーブ侵食時に1から始まり、同位置への再侵食で+1され最大4まで上昇する（4到達でゲーム終了）。
- **消去条件:** おじゃまタイルに隣接するタイルでマッチが発生するか、アイテムの消去範囲内に含まれると、耐久値が1減る。スプーンで直接タップした場合も耐久値が1減る。耐久値が0になるとおじゃまタイルは消滅する。
- **スワイプ移動可能:** おじゃまタイルは通常タイルと同様にスワイプで隣接タイルと入れ替えられる。ただし入れ替え自体は手数を消費せず、入れ替えた結果マッチが成立した場合のみ手数を消費する。
- **落下しない:** おじゃまタイルの下のタイルが消えても、おじゃまタイル自体は落下しない（位置が固定される）。
- **すり抜け落下（Clear / Survivalモード）:** 通常タイルはおじゃまタイルをすり抜けて落下する。おじゃまタイルは固定されたまま、その上にある通常タイルは下方の空きスペースまで貫通して落下する。おじゃまタイルが消滅した場合も同様に、上のタイルがすり抜けて落下する。
- **マッチに参加しない:** おじゃまタイルは通常タイルのマッチ判定には関与しない。
- Clearモードのおじゃまタイルの配置数・耐久値はシード値によって決定される。Survivalモードの侵食位置はシード値とウェーブ番号から決定論的に算出される。

### 3.6. スコア計算（暫定・要バランス調整）

#### 3.6.1. マッチ消去（野菜タイル）

- **基礎点:** 1タイル消去 = 10点
- **連鎖倍率:** N連鎖目の消去は ×N倍。プレイヤーの操作（スワイプ/タップ）で直接消えるのが1連鎖目、落下やアイテム誘爆で自然に消えるのが2連鎖目以降。
  - アイテム効果の後に続く連鎖は「誘爆の段数 + 1」連鎖目から数える（起動したアイテム・スプーン・合成の効果を1段目とし、同じ深さの誘爆は何個でも1段）。タップ・スワイプ・スプーン・合成と、Survival の侵食による強制発動で共通。
- **同時消しボーナス:** 同一連鎖ステップ内で複数マッチが成立した場合、2箇所目以降は1箇所あたり +30点の固定ボーナス。

#### 3.6.2. アイテム効果

アイテムの起動（タップ・スワイプ）やマッチ連鎖による誘爆で消去されたタイルには、アイテム種別ごとの基礎点が適用される。

| アイテム | 基礎点/タイル |
|---|---|
| スプーン | 10点 |
| ハサミ | 20点 |
| 食器セット | 30点 |
| サラダボウル | 40点 |

- **誘爆チェーン倍率:** アイテム効果が別のアイテムを誘爆した場合、誘爆の深さに応じて倍率が加算される。直接起動 = ×1.0、1段目誘爆 = ×1.5、2段目 = ×2.0、…（`×(1 + 0.5 × depth)`）。
- **合成効果:** 合成で消去されたタイルには、構成する2つのアイテムのうち高い方の基礎点が適用される。
- **全消しボーナス:** サラダボウル×サラダボウルの全消し時 +1000点。

#### 3.6.3. 残存アイテム自動発動（Sprintモードのみ）

規定手数到達（または詰み）でゲーム終了した際、盤上に残っているアイテムを1つずつ自動的に発動する。自動発動でもスコアが加算され、連鎖・誘爆も通常通り処理される。ただし、自動発動中の連鎖では新たなアイテムは生成されない。また、合成アイテムの生成・発動も行われない。

**計算例:**
- 1連鎖目：3タイル消去 → 10 × 3 × 1 = 30点
- 2連鎖目：3タイル消去 → 10 × 3 × 2 = 60点
- 3連鎖目：4タイル消去 → 10 × 4 × 3 = 120点
- 1手の合計 = 210点
- ハサミ(横)起動：8タイル消去 → 20 × 8 = 160点
- ハサミが食器セットを誘爆：8タイル消去 → 30 × 8 × 1.5 = 360点

※ 数値はプレイテストを経て調整する前提の仮値。

### 3.7. ゲームモード

デイリーシードに対して4つのモードが用意される。プレイ開始時にモードを選択する。

**Sprint（メインモード）:**
- 規定手数（暫定15手）以内でハイスコアを目指す。
- 規定手数に達した時点、または規定手数前に詰んだ時点（有効なスワイプなし かつ アイテムなし）でゲーム終了。
- スワイプ（マッチ成立時のみ有効）とアイテムのタップ起動がそれぞれ1手としてカウントされる。連鎖・落下・誘爆は手数に含まない。スプーン起動後の任意マス選択も手数を消費しない。
- 終了時に盤上の残存アイテムが自動発動され、スコアが加算される（§3.6.3）。
- **規定手数（暫定）: 全シード共通15手。** プレイテストを経て調整する前提の仮値。
- ランキングはスコアの高い順。

**Clear:**
- 盤上に配置されたおじゃまタイル（§3.5）を全て除去するまでの手数の少なさを競う。
- 全おじゃまタイル除去でクリア。スコアは他モードと同様にマッチ・連鎖・アイテム効果で加算される。
- 詰み状態（有効なスワイプなし かつ アイテムなし かつ おじゃまタイル残存）になった場合はクリア失敗。
- ランキングはクリア優先、同条件なら手数の少ない順（同手数ならスコアの高い順）。

**Survival:**
- ウェーブ制のおじゃまタイル侵食からできるだけ長く生き残るモード。
- **初期盤面:** おじゃまタイルは配置されていない（通常の野菜盤面でスタート）。
- **ウェーブ侵食:** 一定ターン経過ごとにウェーブが発生し、シード値とウェーブ番号から決定論的に算出された位置へおじゃまタイルが侵食する。
  - ウェーブ間隔: **5ターン**ごと（ウェーブ1 = 5手目終了時、ウェーブ2 = 10手目終了時、…）
  - 侵食個数: 4個ずつ増え最大20個で頭打ち（ウェーブ1 = 12個、2 = 16個、3以降 = 20個）
  - 侵食位置の予告: 次のウェーブの **2ターン前** から予定位置を盤面上にマーカー表示する。
- **侵食位置の処理（2フェーズ）:**
  - **フェーズ1（配置）:** 全侵食位置を順に処理し、おじゃまタイルを配置する。
    1. 既存のおじゃまタイルがある場合: 耐久値を +1 する（最大値は4）。
    2. アイテムまたは通常タイルがある場合: アイテム情報を保存した上で **耐久値1** のおじゃまタイルで上書き設置。
  - **フェーズ2（アイテム強制発動）:** 配置フェーズで保存したアイテムを順に発動する。発動時はおじゃまを一時除去してアイテム効果を適用（落下・補充・連鎖含む）。アイテムが発動した位置のおじゃまは消滅扱いとなり再設置されない。
- **終了条件:** 以下のいずれかを満たした時点で終了。
  - (a) おじゃまタイルの耐久値が 4 に到達した瞬間（即死）
  - (b) どのスワイプ操作を行ってもマッチが成立しない盤面状態になった時（詰み）
- **スコア:** 通常のマッチ・連鎖・アイテム効果で加算される。終了時点の累計スコアが最終スコア。
- ランキングは到達した手数が多い順（同手数ならスコアの高い順）。
- ※ ウェーブ間隔・侵食個数・予告リードタイムの数値はプレイテストを経て調整する前提の仮値。

**Cascade:**
- 4色（通常5色から1色減）・おじゃまなしの盤面で15手プレイし、連鎖ポイント（Cascade Points, CP）を競う。
- 色数が少ないため連鎖が発生しやすく、戦略的な連鎖構築が求められるモード。
- **ネクスト表示:** 各列の次に落ちてくるタイル4個をボード上部に縦積みでプレビュー表示。プレイヤーが連鎖を計画的に組み立てるための情報。
- **CPスコアリング:** 連鎖ポイント（CP）= 2連鎖以上のchainIndexの累積合計。例: 4連鎖なら+2,+3,+4で合計9CP。安定した連鎖構築が報われつつ、長連鎖にも自然な傾斜がある。
- **連鎖マイルストーンボーナス:** 1ゲーム中に初めて特定連鎖数に到達するとCPボーナスが加算される。各マイルストーンは1ゲームあたり1回のみ。上位直接達成で下位も同時解除。
  | 達成連鎖数 | ボーナスCP |
  |---|---|
  | 3連鎖 | +10 |
  | 5連鎖 | +25 |
  | 7連鎖 | +50 |
- **連鎖ポテンシャル表示:** 盤面の全有効スワイプを試算し、最大到達連鎖数を「MAX N連鎖」バッジで表示。N≥3でハイライト。UI表示のみでゲーム状態に影響しない。
- **連鎖メーター:** 連鎖の進行を9セグメント（2連鎖〜10連鎖）の横型ゲージで可視化。連鎖完了後、次の手まで最終到達段で点灯維持。
- **ベスト更新演出:** 1ゲーム内で最大連鎖数を更新した瞬間に「NEW BEST: N連鎖!」をオーバーレイ表示。
- **連鎖エフェクト:** 2連鎖以上が発生した際、連鎖数とCP加算をスコアと同じスタイルのフローティングテキストで表示。マイルストーン達成時は別途ゴールド色のフローティングラベル。
- **キラキラ野菜:** Cascadeモード限定。通常タイルの一部がキラキラ状態になり、消去時に1個あたり+1 CPが加算される（連鎖倍率の影響なし）。マッチ判定には一切影響しない。
  - **初期配置:** 自動消去後の安定盤面に、シード由来の2個を配置。
  - **補充タイル:** 各列の補充タイルストリームで独立RNG（シード由来）により10%の確率でキラキラ状態になる。
  - **ネクスト表示:** キラキラ状態の補充タイルも星マークで視覚的に反映。
  - **見た目:** 通常タイルと同じ色・形状で、右上に星マーク+きらめきアニメーションで識別。色覚対応（形+動きで識別可能）。
  - パラメータ: 初期キラキラ数=2、補充確率=10%、ボーナスCP/個=+1（全て定数化）
- 規定手数（15手）に達した時点、または詰んだ時点でゲーム終了。
- ランキングはCPの高い順（同CPならトータルスコアの高い順）。
- 終了時のアイテム自動発動はなし（Sprintのみの機能）。
- **規定手数: 全シード共通15手。**

**ランキング構成:**

| モード | ランキング基準 | 位置づけ |
|---|---|---|
| Sprint | スコアの高い順 | メインランキング |
| Clear | 手数の少ない順 | サブランキング |
| Survival | 到達手数の多い順（同手数ならスコア高い順） | サブランキング |
| Cascade | CPの高い順（同CPならスコア高い順） | サブランキング |

- 全ランキングはシードごとに存在する
- デイリーシードのHOMEショートカットはSprintランキングを表示

### 3.8. シード管理

- **デイリーシード:** 日付ベースで生成され、UTC 0時に更新される。全プレイヤーが同じシードに挑戦する。
- **過去のデイリーシード:** カレンダーUIで過去のデイリーシードとランキングを閲覧・プレイできる。
- **リトライ:** 全シード無制限にリトライ可能。ベストスコアのみ保持される（upsert方式）。Sprint: 最高スコアを保持。Clear: クリア済み優先、同条件なら最少手数を保持。Survival: 最多到達手数を保持。Cascade: 最高CPを保持（同CPならスコア高い方）。
- **シェア:** プレイ結果（スコア・モード・ボード状態）をSNS等に共有できる。
- **Clearモードのシード:** デイリーシードごとに、おじゃまタイルの配置もシード値から決定的に生成される。
- **Cascadeモードのシード:** デイリーシードごとに、4色（5色のうち1色を除外）・おじゃまなしの盤面がシード値から決定的に生成される。

### 3.10. 手順再生（リプレイビューア）

ベストスコアの手順を後から振り返る機能。

**リプレイログの記録:**
- プレイ中の操作（スワイプ・タップ・スプーン選択・合成）を `ReplayAction` 型の配列として記録する。
- スコア送信時にリプレイログも送信される。ベストスコア更新時のみR2に保存される（`replay_log_key`）。
- セッション途中の中断時はsessionStorageにリプレイログも保存し、復帰時に復元する。

**ReplayAction型:**
- `swap`: `{ type: 'swap', pos, dir }` — 通常のスワイプ操作
- `tap`: `{ type: 'tap', pos }` — アイテムのタップ起動
- `scope`: `{ type: 'scope', pos, targetCells }` — スプーンの直接タップ起動
- `scope_swap`: `{ type: 'scope_swap', pos, dir, targetCells }` — スワイプでスプーンを移動後に発動
- `scope_synthesis`: `{ type: 'scope_synthesis', pos1, pos2, targetCells }` — スプーン合成

**再生ビューア（`/replay/:scoreId`）:**
- ランキングモーダルの自分のエントリに再生ボタン（▶）を表示。タップで遷移。
- エンジンの決定性を利用し、シード値 + 操作列から全中間状態を再構築する。
- トランスポートコントロール: 再生/一時停止、ステップ前進/後退、先頭/末尾へジャンプ
- スライダーで任意のステップへジャンプ可能
- 速度切替: 0.5x / 1x / 2x / 4x
- アクションリスト: 全操作の一覧、現在/次のアクションをハイライト表示
- 盤面上で次のアクションの対象セルをハイライト表示

**API:**
- `GET /api/scores/:scoreId/replay`（認証必須、自分のスコアのみ）→ `{ replayLog, seed, mode, moveLimit }`

## 5. 認証・セキュリティ

### 5.1. 認証方式
- **方式:** JWT (JSON Web Token) による認証。リクエストの `Authorization: Bearer <token>` ヘッダで送信。
- **トークン管理:** アクセストークン（1h）とリフレッシュトークン（90d）の2トークン方式。ライブラリは jose。
- **匿名ログインフロー:** 初回アクセス時にクライアント側でUUIDを生成、バックエンドに送信して「ゲストユーザー」としてD1に登録。

### 5.2. アカウント引き継ぎ（マルチデバイス）

1つのアカウントを複数のデバイス/ブラウザで共有する仕組み。引き継ぎ後も元の端末はそのまま利用可能。

**引き継ぎコード発行フロー:**
1. ユーザーが設定画面で「引き継ぎコード発行」をタップ
2. バックエンドが8文字の英数字コードを生成し、KVに `link:{code}` → `userId` を保存（TTL: 10分）
3. コードと有効期限をユーザーに表示

**引き継ぎコード入力フロー:**
1. 別端末で「引き継ぎコードを入力」を選択し、8文字コードを入力
2. バックエンドがKVからコードを検索し、対応する `userId` を取得
3. 新端末の `device_id` を `user_devices` テーブルに登録
4. 対象ユーザーのJWTを発行し、新端末に保存
5. KVからコードを削除（1回限り有効）

**マルチデバイス管理:**
- `user_devices` テーブルで1ユーザーに複数の `device_id` を紐付ける
- 認証時のデバイス検索順序: `user_devices` → `users.device_id`（後方互換）
- 各端末は独立したJWTを保持し、同時にログイン可能
- 新端末にもともと別ユーザーが存在した場合、そのユーザーは孤立する（スコアデータは残るがデバイス紐付けは解除）

**API:**
- `POST /api/account/link-code`（認証必須）→ `{ code, expiresAt }`
- `POST /api/account/link`（認証不要）→ `{ code, deviceId }` → `{ userId, accessToken, refreshToken }`

**将来拡張:**
- Google / Apple ID 連携による外部認証。`user_devices` テーブルと同様の構造で `user_auth_providers` テーブルを追加し、外部プロバイダのID → `userId` のマッピングを管理する。

### 5.3. 不正対策

段階的に対策を強化する。

**初期リリース:**
- **リプレイ検証:** スコア送信時にreplay_log（操作ログ）を送信し、バックエンド側でパズルエンジンを用いてリプレイ検証を行う。シード値の固定とエンジンの決定性により、操作列からスコアを再計算し整合性を確認する。
- **レートリミット:** APIエンドポイントにレートリミットを設定。

**ネイティブ化以降:**
- **デバイス認証:** Apple App Attest (iOS) / Google Play Integrity API (Android) を導入。

## 6. データベース設計 (Cloudflare D1)

## 7. AIエージェント向け 開発フェーズ指示

### Phase 1: Core Engine (`engine/`)

UIを持たない、純粋なTypeScriptによる3マッチエンジンの開発。

**入力:** 盤面サイズ(8×8)、タイル種数(5、Cascadeは4)、シード値、ゲームモード（sprint/clear/survival/cascade）、モード固有パラメータ（Sprint/Cascade: 手数制限 / Survival: ウェーブ設定 / Cascade: 色数）、操作列（スワイプ/タップの座標と方向 + スプーンの選択マス）
**出力:** 各操作後の盤面状態、生成されたアイテム、連鎖情報、累計スコア、現在手数、おじゃまタイル状態、Survivalウェーブ状態（現在のウェーブ番号・次のウェーブまでの残ターン・予告位置）、Cascade CP/最大連鎖数、ゲーム終了判定

**実装する機能:**
1. シード値による決定的な盤面生成（初期自動消去を含む、スコア0・アイテム生成なし）
2. マッチ判定（縦横3以上の直線検出 + 2×2正方形検出）
3. 落下補充処理（重力 + 列ごと独立RNGストリームによる決定的タイル供給、Clear/Survivalモードではおじゃまタイルをすり抜けて落下）
4. 連鎖処理（落下後の再マッチ判定ループ）
5. アイテム生成判定（パターン認識と優先順位、2×2と直線の重複判定を含む）
6. アイテム起動・誘爆処理（スプーンの周囲4マス消去 + ユーザー選択マス消去、連鎖時は周囲4マスのみ）
7. アイテム合成処理（全パターン、スプーン合成時の周囲4マス追加消去を含む）
8. サラダボウル×サラダボウル全消し時のアイテム残留＋再補充
9. おじゃまタイル処理（Clear: シード値による配置生成 / Survival: ウェーブ制侵食。耐久値管理、消去判定、非落下挙動）
10. スコア計算（基礎点 × 連鎖倍率 + 同時消しボーナス + アイテム効果点 + 全消しボーナス + 残存アイテム自動発動）
11. 手数カウント（スワイプ・タップ操作を1手としてカウント、連鎖・落下・誘爆・スプーンの選択は含まない）
12. ゲーム終了判定（Sprint: 規定手数到達 or 詰み / Clear: 全おじゃまタイル除去 or 詰み / Survival: おじゃまタイル耐久値4到達 or 詰み / Cascade: 規定手数到達 or 詰み）
13. Survivalウェーブ処理（Nターン経過ごとにシード×ウェーブ番号から決定論的に侵食位置を算出、アイテム強制発動→おじゃまタイル設置、予告マーカー管理）
14. Cascadeモード対応（4色盤面生成、CPスコアリング、ネクストタイルプレビュー生成）

**テスト:** Vitestを用いた単体テスト。各機能に対して正常系・境界値・エッジケースのテストを記述。特にシード値の決定性（同一シード・同一操作で常に同一結果）を検証するテストを必須とする。

### Phase 2: Frontend UI (`frontend/`)

Vue.jsを用いた画面構築。

**実装する画面:**
1. **HOMEダッシュボード:** 当日のデイリーシードへのショートカット（モード選択含む）、Sprintランキングプレビュー、過去デイリーのカレンダーUI
2. **パズル画面:** エンジンを組み込み、モード選択（Sprint/Clear/Survival/Cascade）、手数カウント/残り手数表示、おじゃまタイル表示（Clear/Survivalモード）、Survivalウェーブ情報表示（現在ウェーブ番号・次ウェーブまでの残ターン・侵食予告マーカー）、Cascadeネクスト/CP表示、スワイプ操作・タップ操作・スプーン選択UI・アニメーション・スコア表示を実装。プレイ後のスコアシェアUIを含む。

### Phase 3: Backend API (`backend/`)

Cloudflare Workers + D1によるAPI実装。

**実装するAPI:**
1. **認証:** 匿名ログイン（UUID→JWT発行）、トークンリフレッシュ
2. **デイリーシード:** 当日シード取得、過去デイリー一覧（カレンダー用）
3. **スコア送信:** モード別スコア送信、リプレイ検証（エンジンを用いたサーバーサイド再計算）
4. **ランキング:** シード×モードごとのスコアランキング、KVキャッシュ戦略（モード別にキーを分離）
5. **シェア:** シェア用データ生成（スコア・モード・ボード状態のスナップショット）
6. **実績:** 実績解除判定、実績一覧取得
7. **リプレイ:** スコアに紐づくリプレイログの取得（R2から読み出し）
8. **不正対策:** 全APIエンドポイントへのレートリミット設定

### Phase 3.10: Survivalモードリニューアル

旧「5手ごと区間スコアノルマ」型を廃止し、Clearモードの「盤面のおじゃまタイル管理」というコア体験を土台にしたウェーブ侵食型に刷新する。

- **ウェーブ制侵食** — シード値とウェーブ番号から決定論的に算出した位置へおじゃまタイル（耐久値1）を設置。5ターンごとに発生、侵食個数は 12 → 16 → 20 と増加（最大20個）。
- **予告マーカー** — 次ウェーブの2ターン前から侵食予定位置を盤面上に表示。
- **強制発動** — 侵食位置にアイテムがある場合は発動してからおじゃまタイルを設置。走査順は行×列昇順で決定論的。
- **耐久値の積み上げ** — 既存のおじゃまタイルへの再侵食は耐久値+1。耐久値4到達で即ゲームオーバー。
- **重力:** Clearモード同様 `passThroughObstacles=true`（非おじゃまタイルがおじゃまをすり抜けて下詰め）。
- **ランキング・実績:** 既存のルール維持（到達手数降順、同手数ならスコア降順）。旧「区間ノルマ」用のi18nキー（`survivalQuota*` 等）は廃止し、ウェーブ情報表示用キー（`survivalWave*` 等）を追加する。
