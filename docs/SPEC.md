# SPEC.md (Architecture & Requirements Guide)

※ ゲーム名: **Vege-Table**。旧称「Project Tomado」からピボット完了。ドメイン `3tomado.app` は旧称のまま。

## 1. プロジェクト概要

毎日出題されるデイリーパズル（3マッチ）でスコアを競うカジュアルゲーム。Wordleのように「今日の問題」を全プレイヤーが共有し、結果をSNSでシェアする体験を軸とする。

### 1.1. コアコンセプト
- **デイリーパズル:** 毎日UTC 0時に新しいシード（パズル問題）が出題される。全プレイヤーが同じ盤面に挑戦する。
- **シード値固定:** シードごとに初期盤面と落下ピースの順序が完全に一致する。同じシードを何度リトライしても同じ操作で同じ結果が得られる。
- **無制限リトライ:** デイリーシードは何度でもプレイ可能。ベストスコアがランキングに反映される。
- **過去のデイリー:** カレンダーUIで過去のデイリーシードを遡ってプレイできる。
- **3つのゲームモード:** Sprint（手数制限ハイスコア）、Clear（おじゃまタイル除去）、Survival（スコアノルママラソン）。詳細は §3.7。

### 1.2. ランキングとシェア
- ランキングはシードごと・モードごとに存在する。Sprintがメインモード。
- HOME画面からは当日のデイリーシードのSprintランキングにショートカットでアクセスできる。
- プレイ結果はスコアとボードの状態をSNS等にシェアできる。シェア内容にはシード情報・モード・スコアを含む。
- ランキングにはプレイヤーの表示名（display_name）が表示される。
- 自分のランク（順位）がランキングモーダル上部に強調表示される。

### 1.3. ユーザー名（表示名）
- プレイヤーは任意のタイミングで表示名（display_name）を設定・変更できる。
- 最大20文字。未設定の場合は「Anonymous」として表示される。
- ランキングやスコア共有時にこの表示名が使用される。
- HOME画面から設定可能。

### 1.4. 実績（トロフィー）
- パズルプレイを通じて実績を解除できるコレクション要素。報酬なしの純粋なトロフィーシステム。
- 詳細は §3.9。

## 2. UI/UX と世界観テーマ
- **テーマ:** 「野菜」
- **タイル:** 5種類の色の異なる野菜アイコン。視認性を重視し、色だけでなくシルエットでも区別できるデザインとする。
- **アイテム:** 調理器具をモチーフとする（虫めがね、はさみ、カッター、クリップ、コーヒーカップ）。※アイテム名は旧テーマの仮称を引き継いでおり、野菜テーマに合わせて別途リネームする。
- **おじゃまタイル:** Clearモードで登場する除去対象の障害物。
- **画面構成:** スマートフォンに最適化。HOMEダッシュボード、パズル画面、カレンダー（過去デイリー）、ランキング。
- **ダークモード:** CSS Custom Properties によるテーマ色定義。`prefers-color-scheme` 自動検出 + 手動トグル。
- **i18n:** 日本語/英語対応。ブラウザ言語自動検出 + 手動切替。

## 3. パズルルール詳細

### 3.1. 盤面基本ルール
- **盤面サイズ:** 8×8の正方形
- **タイルの種類:** 5種類の野菜
- **配置決定:** シード値を元にした擬似乱数でタイルの配置と落下順序が決定される。盤面外（下方向）にも無限にタイルが並んでいるものとする。
- **初期盤面:** シード値に基づいてランダム配置した後、マッチが存在する場合は自動消去＋落下を安定状態になるまで繰り返す。この初期自動消去ではスコアは加算されず、アイテムも生成されない。自動消去完了後の盤面がプレイヤーの開始盤面となる。
- **マッチ判定:** 以下の2種類のパターンでマッチが成立し、該当するタイルが消去される。
  - **直線マッチ:** 同種のタイルが縦または横に3つ以上連続で並んでいる場合。
  - **2×2マッチ:** 同種のタイルが縦横2×2の正方形に並んでいる場合。
- **操作:** プレイヤーは隣接するタイルをスワイプで入れ替えられる。ただし、入れ替えの結果マッチが成立する場合のみ有効。
- **落下補充:** タイルが消えた後、上方のタイルが重力で落下し、空いたスペースにはシード値に基づく新しいタイルが上から補充される。落下後にマッチが発生した場合、連鎖として続けて消去される。補充タイルは列ごとに独立した擬似乱数ストリーム（シード値由来）で生成されるため、同じシードであれば各列のN番目の補充タイルは常に同じ色になる（プレイ順序に依存しない決定性）。
- **ゲーム終了条件:** ゲームモードにより異なる（詳細は §3.7）。

### 3.2. アイテム生成ルール

ゲーム中に特定のパターンでタイルを消すと、その位置にアイテムが生成される。

| 消去パターン | 生成アイテム | 効果概要 |
|---|---|---|
| 2×2正方形 | 虫めがね | 周囲縦横4マス消去 + 任意1マス消去 |
| 横4マス直線 | はさみ | 縦一列消去 |
| 縦4マス直線 | カッター | 横一列消去 |
| 5マス以上連結（非直線） | クリップ | 周囲2マス消去 |
| 縦または横5マス直線 | コーヒーカップ | 対象色の全消し |

**優先順位:** 複数の生成条件に同時に該当する場合、より上位のアイテムが1つだけ生成される。優先順は コーヒーカップ > クリップ > カッター = はさみ > 虫めがね。ただし、2×2パターンと3直線マッチが重複した場合は虫めがねが成立する。2×2パターンが4直線以上やL/T字型の5マス以上連結と重複した場合は上位アイテムが優先され虫めがねは生成されない。

**生成位置:**
- プレイヤーのスワイプ操作に起因する場合 → スワイプ操作の起点位置
- アイテム効果による連鎖消去に起因する場合 → 消去されたタイル群の中央

### 3.3. アイテム起動ルール

- **起動方法:** タップ（1手消費）またはスワイプで隣接タイルと入れ替え。
- **誘爆:** アイテムの効果範囲内に別のアイテムが存在する場合、そのアイテムも連鎖的に発動する。

**各アイテムの効果:**

| アイテム | タップ / スワイプ起動 | 連鎖発動（他アイテムに巻き込まれた場合） |
|---|---|---|
| 虫めがね | 1手消費で起動。周囲縦横4マス（上下左右）を消去した後、ユーザーが盤上の任意の1マスを選択して消去する（選択自体は手数を消費しない）。選択したマスがアイテムの場合、そのアイテムを発動する。 | 周囲縦横4マスを消去する（ユーザー選択なし）。 |
| はさみ | タップまたはスワイプで縦一列のタイルを全て消去 | 同左 |
| カッター | タップまたはスワイプで横一列のタイルを全て消去 | 同左 |
| クリップ | タップまたはスワイプで周囲2マス分のタイルを消去 | 同左 |
| コーヒーカップ | スワイプ時：入れ替え先のタイルと同種のタイルを盤上から全て消去。タップ時：上隣から時計回り順で最初に見つかるタイルと同種のタイルを盤上から全て消去 | タップ時と同様（時計回り探索） |

※ カッターアイコンは、はさみを90度回転させたもの（縦=はさみ、横=カッター）。

### 3.4. アイテム合成ルール

アイテム同士をスワイプで入れ替えた場合、特殊な合成効果が発動する。虫めがねの合成では、元の位置で周囲縦横4マスの消去効果も追加で発動する。

| 組み合わせ | 効果 |
|---|---|
| 虫めがね + 虫めがね | 両方の位置で周囲縦横4マスを消去 + ユーザーが盤上の任意の3マスを選択して消去する |
| 虫めがね + はさみ | 虫めがねの位置で周囲縦横4マスを消去 + ユーザーが選んだ任意の1マスを起点に縦一列消去 |
| 虫めがね + カッター | 虫めがねの位置で周囲縦横4マスを消去 + ユーザーが選んだ任意の1マスを起点に横一列消去 |
| 虫めがね + クリップ | 虫めがねの位置で周囲縦横4マスを消去 + ユーザーが選んだ任意の1マスを起点に周囲2マス消去 |
| 虫めがね + コーヒー | 虫めがねの位置で周囲縦横4マスを消去 + コーヒーの縦横1マス隣から時計回り順で最初に見つかるタイルと同種のタイルを盤上から全て消去 |
| はさみ + はさみ / はさみ + カッター / カッター + カッター | スワイプ位置を基準に縦横十字に消去 |
| はさみ + クリップ | 縦3列を消去 |
| カッター + クリップ | 横3列を消去 |
| クリップ + クリップ | 周囲3マスを消去 |
| コーヒー + はさみ | 対象色の全タイルそれぞれから縦一列消去が発動 |
| コーヒー + カッター | 対象色の全タイルそれぞれから横一列消去が発動 |
| コーヒー + クリップ | 対象色の全タイルそれぞれから周囲2マス消去が発動 |
| コーヒー + コーヒー | 盤上のタイルを全て消去。**ただしアイテムは誘爆せず盤上に残留する。** 全消し後、アイテムはその位置に留まり、周囲の空きマスにシード値に基づく新しいタイルが降ってくる。全消しボーナス +1000点。 |

### 3.5. おじゃまタイル（Clearモード専用）

- おじゃまタイルはシード値に基づいて盤上に配置される障害物である。
- 各おじゃまタイルには耐久値（1〜3）が設定される。
- **消去条件:** おじゃまタイルに隣接するタイルでマッチが発生するか、アイテムの消去範囲内に含まれると、耐久値が1減る。虫めがね（スプーン）で直接タップした場合も耐久値が1減る。耐久値が0になるとおじゃまタイルは消滅する。
- **落下しない:** おじゃまタイルの下のタイルが消えても、おじゃまタイル自体は落下しない（位置が固定される）。
- **すり抜け落下（Clearモード）:** 通常タイルはおじゃまタイルをすり抜けて落下する。おじゃまタイルは固定されたまま、その上にある通常タイルは下方の空きスペースまで貫通して落下する。おじゃまタイルが消滅した場合も同様に、上のタイルがすり抜けて落下する。
- **マッチに参加しない:** おじゃまタイルは通常タイルのマッチ判定には関与しない。
- おじゃまタイルの配置数・耐久値はシード値によって決定される。

### 3.6. スコア計算（暫定・要バランス調整）

#### 3.6.1. マッチ消去（野菜タイル）

- **基礎点:** 1タイル消去 = 10点
- **連鎖倍率:** N連鎖目の消去は ×N倍。プレイヤーの操作（スワイプ/タップ）で直接消えるのが1連鎖目、落下やアイテム誘爆で自然に消えるのが2連鎖目以降。
- **同時消しボーナス:** 同一連鎖ステップ内で複数マッチが成立した場合、2箇所目以降は1箇所あたり +30点の固定ボーナス。

#### 3.6.2. アイテム効果

アイテムの起動（タップ・スワイプ）やマッチ連鎖による誘爆で消去されたタイルには、アイテム種別ごとの基礎点が適用される。

| アイテム | 基礎点/タイル |
|---|---|
| 虫めがね | 10点 |
| はさみ / カッター | 20点 |
| クリップ | 30点 |
| コーヒーカップ | 40点 |

- **誘爆チェーン倍率:** アイテム効果が別のアイテムを誘爆した場合、誘爆の深さに応じて倍率が加算される。直接起動 = ×1.0、1段目誘爆 = ×1.5、2段目 = ×2.0、…（`×(1 + 0.5 × depth)`）。
- **合成効果:** 合成で消去されたタイルには、構成する2つのアイテムのうち高い方の基礎点が適用される。
- **全消しボーナス:** コーヒー×コーヒーの全消し時 +1000点。

#### 3.6.3. 残存アイテム自動発動（Sprintモードのみ）

規定手数到達（または詰み）でゲーム終了した際、盤上に残っているアイテムを1つずつ自動的に発動する。自動発動でもスコアが加算され、連鎖・誘爆も通常通り処理される。

**計算例:**
- 1連鎖目：3タイル消去 → 10 × 3 × 1 = 30点
- 2連鎖目：3タイル消去 → 10 × 3 × 2 = 60点
- 3連鎖目：4タイル消去 → 10 × 4 × 3 = 120点
- 1手の合計 = 210点
- カッター起動：8タイル消去 → 20 × 8 = 160点
- カッターがクリップを誘爆：8タイル消去 → 30 × 8 × 1.5 = 360点

※ 数値はプレイテストを経て調整する前提の仮値。

### 3.7. ゲームモード

デイリーシードに対して3つのモードが用意される。プレイ開始時にモードを選択する。

**Sprint（メインモード）:**
- 規定手数（暫定15手）以内でハイスコアを目指す。
- 規定手数に達した時点、または規定手数前に詰んだ時点（有効なスワイプなし かつ アイテムなし）でゲーム終了。
- スワイプ（マッチ成立時のみ有効）とアイテムのタップ起動がそれぞれ1手としてカウントされる。連鎖・落下・誘爆は手数に含まない。虫めがね起動後の任意マス選択も手数を消費しない。
- 終了時に盤上の残存アイテムが自動発動され、スコアが加算される（§3.6.3）。
- **規定手数（暫定）: 全シード共通15手。** プレイテストを経て調整する前提の仮値。
- ランキングはスコアの高い順。

**Clear:**
- 盤上に配置されたおじゃまタイル（§3.5）を全て除去するまでの手数の少なさを競う。
- 全おじゃまタイル除去でクリア。クリア時の手数がスコアとなる。
- 詰み状態（有効なスワイプなし かつ アイテムなし かつ おじゃまタイル残存）になった場合はクリア失敗。
- ランキングは手数の少ない順。

**Survival:**
- 5手ごとにスコアノルマが設定され、ノルマを達成し続ける限りゲームが続く。
- 各5手区間で独立してスコアが判定される（得点は次の区間に引き継がない）。例: 最初の5手で300点→次の5手で400点→その次の5手で500点…。
- 5手ごとのチェックポイントで**その区間のスコア**がノルマに達していなければゲームオーバー。チェックポイント通過時に区間スコアがリセットされる。
- ノルマは段階的に重くなる（区間0: 300点、区間1: 400点、区間2: 500点、… +100ずつ増加）。
- ランキングは到達した手数が多い順（同手数ならスコアの高い順）。
- ※ ノルマの具体的な数値はプレイテストを経て調整する前提の仮値。

**ランキング構成:**

| モード | ランキング基準 | 位置づけ |
|---|---|---|
| Sprint | スコアの高い順 | メインランキング |
| Clear | 手数の少ない順 | サブランキング |
| Survival | 到達手数の多い順（同手数ならスコア高い順） | サブランキング |

- 全ランキングはシードごとに存在する
- デイリーシードのHOMEショートカットはSprintランキングを表示

### 3.8. シード管理

- **デイリーシード:** 日付ベースで生成され、UTC 0時に更新される。全プレイヤーが同じシードに挑戦する。
- **過去のデイリーシード:** カレンダーUIで過去のデイリーシードとランキングを閲覧・プレイできる。
- **リトライ:** 全シード無制限にリトライ可能。ベストスコアのみ保持される（upsert方式）。Sprint: 最高スコアを保持。Clear: クリア済み優先、同条件なら最少手数を保持。Survival: 最多到達手数を保持。
- **シェア:** プレイ結果（スコア・モード・ボード状態）をSNS等に共有できる。
- **Clearモードのシード:** デイリーシードごとに、おじゃまタイルの配置もシード値から決定的に生成される。

### 3.9. 実績（トロフィー）

パズルプレイを通じて解除できるコレクション要素。報酬はなく、純粋なトロフィーシステムとして機能する。

**実績カテゴリ（例）:**
- **Sprint系:** N連鎖達成、15手でN点以上 等
- **Clear系:** N手以内にクリア、耐久値3のおじゃまタイルをアイテムで一撃消去 等
- **Survival系:** N手到達 等
- **コレクション系:** N日連続プレイ、全アイテム種を1ゲームで生成 等

**可視性:**
- 大半の実績は未解除の状態でも条件が表示される（プレイヤーが狙える）。
- 一部は「秘密の実績」として条件が隠され、解除時に初めて内容が明かされる。

※ 実績の具体的なリストと条件値は別途定義する。

### 3.10. エラーメッセージング

API通信失敗時にユーザーへ適切なフィードバックを提供する。

**表示方式:** トースト通知（画面下部、数秒で自動消去、手動閉じ可能）

**エラー種別と表示:**

| エラー種別 | メッセージ例 | リトライ |
|---|---|---|
| スコア送信失敗 | 「スコアの送信に失敗しました。後で自動的に再送されます」 | 自動（オフラインキュー） |
| ランキング取得失敗 | 「ランキングを取得できませんでした」 | 手動（再読み込み） |
| 認証エラー | 「認証に失敗しました。再ログインしています…」 | 自動（トークンリフレッシュ） |
| ネットワークエラー | 「ネットワークに接続できません。オフラインモードで動作中です」 | 自動（オンライン復帰時） |

**設計原則:**
- ゲームプレイは中断しない（ローカルデータで動作継続）
- 送信系エラーはオフラインキュー（§3.11）と連携
- 取得系エラーはキャッシュデータがあればそれを表示

### 3.11. オフラインリトライ

API失敗時にリクエストをキューに保存し、オンライン復帰時に自動リトライする。

**対象リクエスト:**
- スコア送信（`POST /api/scores`）
- 実績同期（将来）

**キュー仕様:**
- localStorage に保存（`offline_queue` キー）
- 各エントリ: `{ url, method, body, createdAt }`
- リトライ上限: 3回（超過時はキューから除外し、ユーザーに通知）
- 有効期限: 24時間（期限切れエントリは起動時に削除）

**リトライトリガー:**
- `online` イベント検知時
- アプリ起動時（キューが空でない場合）
- 手動リトライボタン押下時

### 4.2. フロントエンド
- **フレームワーク:** Vue.js (Composition API, `<script setup>`)
- **状態管理:** Pinia
- **i18n:** vue-i18n（日本語/英語）
- **タッチ操作最適化:** VueUse (`usePointerSwipe`等) を活用。パズル盤面には `touch-action: none;` を適用しブラウザ標準のスワイプ挙動を無効化。描画パフォーマンス最適化のため、アニメーションは必ず `transform` を使用する。
- **テスト:** Vitest（単体テスト）
- **ハイブリッド化:** Capacitor (将来的にネイティブアプリ化する際に使用)

### 4.3. バックエンド & インフラ
- **プラットフォーム:** Cloudflare Workers (TypeScript, Hono)
- **データベース:** Cloudflare D1 (SQLiteベースのRDBMS)
- **キャッシュ/KVS:** Cloudflare KV (デイリーシードやランキングデータの高速配信)
- **オブジェクトストレージ:** Cloudflare R2（replay_log等の大容量データ保存）

### 4.4. パズルエンジン (`engine/`)
- 純粋なTypeScriptで実装し、UIやネットワークに一切依存しない。
- 盤面生成、マッチ判定、落下処理、連鎖、アイテム生成・起動・合成、おじゃまタイル処理、スコア計算を全て純粋関数として提供する。
- シード値を入力として与えた場合に完全に決定的な結果を返すことを保証する。
- フロントエンド（ゲームUI）とバックエンド（リプレイ検証）の双方から利用される。

## 5. 認証・セキュリティ

### 5.1. 認証方式
- **方式:** JWT (JSON Web Token) による認証。リクエストの `Authorization: Bearer <token>` ヘッダで送信。
- **トークン管理:** アクセストークン（1h）とリフレッシュトークン（90d）の2トークン方式。ライブラリは jose。
- **匿名ログインフロー:** 初回アクセス時にクライアント側でUUIDを生成、バックエンドに送信して「ゲストユーザー」としてD1に登録。

### 5.2. アカウント引き継ぎ（マルチデバイス）

1つのアカウントを複数のデバイス/ブラウザで共有する仕組み。引き継ぎ後も元の端末はそのまま利用可能。

**引き継ぎコード発行フロー:**
1. ユーザーが設定画面で「引き継ぎコード発行」をタップ
2. バックエンドが8文字の英数字コードを生成し、KVに `link:{code}` → `userId` を保存（TTL: 10分）
3. コードと有効期限をユーザーに表示

**引き継ぎコード入力フロー:**
1. 別端末で「引き継ぎコードを入力」を選択し、8文字コードを入力
2. バックエンドがKVからコードを検索し、対応する `userId` を取得
3. 新端末の `device_id` を `user_devices` テーブルに登録
4. 対象ユーザーのJWTを発行し、新端末に保存
5. KVからコードを削除（1回限り有効）

**マルチデバイス管理:**
- `user_devices` テーブルで1ユーザーに複数の `device_id` を紐付ける
- 認証時のデバイス検索順序: `user_devices` → `users.device_id`（後方互換）
- 各端末は独立したJWTを保持し、同時にログイン可能
- 新端末にもともと別ユーザーが存在した場合、そのユーザーは孤立する（スコアデータは残るがデバイス紐付けは解除）

**API:**
- `POST /api/account/link-code`（認証必須）→ `{ code, expiresAt }`
- `POST /api/account/link`（認証不要）→ `{ code, deviceId }` → `{ userId, accessToken, refreshToken }`

**将来拡張:**
- Google / Apple ID 連携による外部認証。`user_devices` テーブルと同様の構造で `user_auth_providers` テーブルを追加し、外部プロバイダのID → `userId` のマッピングを管理する。

### 5.3. 不正対策

段階的に対策を強化する。

**初期リリース:**
- **リプレイ検証:** スコア送信時にreplay_log（操作ログ）を送信し、バックエンド側でパズルエンジンを用いてリプレイ検証を行う。シード値の固定とエンジンの決定性により、操作列からスコアを再計算し整合性を確認する。
- **レートリミット:** APIエンドポイントにレートリミットを設定。

**ネイティブ化以降:**
- **デバイス認証:** Apple App Attest (iOS) / Google Play Integrity API (Android) を導入。

## 6. データベース設計 (Cloudflare D1)

- **`users`**: `id` (UUID), `display_name` (表示名, 最大20文字), `device_id`, `created_at`
- **`user_devices`**: `user_id` (FK→users), `device_id` (UNIQUE), `linked_at` — マルチデバイス対応。引き継ぎコードで紐付けた追加デバイスを管理。
- **`puzzle_seeds`**: `seed_id`, `seed_value` (ユニーク), `share_code` (ユニーク, 6〜8文字の英数字), `daily_date` (YYYY-MM-DD), `created_at`
- **`play_scores`**: `id`, `user_id`, `seed_id`, `mode` (sprint / clear / survival), `score`, `move_count` (実際の手数), `move_limit` (Sprint: 規定手数, nullable), `is_cleared` (Clearモードのクリア可否), `replay_log_key` (R2のオブジェクトキー), `created_at`
- **`achievements`**: `id`, `user_id`, `achievement_type`, `current_value`, `is_unlocked`, `unlocked_at`

## 7. AIエージェント向け 開発フェーズ指示

### Phase 1: Core Engine (`engine/`)

UIを持たない、純粋なTypeScriptによる3マッチエンジンの開発。

**入力:** 盤面サイズ(8×8)、タイル種数(5)、シード値、ゲームモード（sprint/clear/survival）、モード固有パラメータ（Sprint: 手数制限 / Survival: ノルマテーブル）、操作列（スワイプ/タップの座標と方向 + 虫めがねの選択マス）
**出力:** 各操作後の盤面状態、生成されたアイテム、連鎖情報、累計スコア、現在手数、おじゃまタイル状態、Survivalノルマ判定、ゲーム終了判定

**実装する機能:**
1. シード値による決定的な盤面生成（初期自動消去を含む、スコア0・アイテム生成なし）
2. マッチ判定（縦横3以上の直線検出 + 2×2正方形検出）
3. 落下補充処理（重力 + 列ごと独立RNGストリームによる決定的タイル供給、Clearモードではおじゃまタイルをすり抜けて落下）
4. 連鎖処理（落下後の再マッチ判定ループ）
5. アイテム生成判定（パターン認識と優先順位、2×2と直線の重複判定を含む）
6. アイテム起動・誘爆処理（虫めがねの周囲4マス消去 + ユーザー選択マス消去、連鎖時は周囲4マスのみ）
7. アイテム合成処理（全パターン、虫めがね合成時の周囲4マス追加消去を含む）
8. コーヒー×コーヒー全消し時のアイテム残留＋再補充
9. おじゃまタイル処理（シード値による配置生成、耐久値管理、消去判定、非落下挙動）
10. スコア計算（基礎点 × 連鎖倍率 + 同時消しボーナス + アイテム効果点 + 全消しボーナス + 残存アイテム自動発動）
11. 手数カウント（スワイプ・タップ操作を1手としてカウント、連鎖・落下・誘爆・虫めがねの選択は含まない）
12. ゲーム終了判定（Sprint: 規定手数到達 or 詰み / Clear: 全おじゃまタイル除去 or 詰み / Survival: ノルマ未達 or 詰み）

**テスト:** Vitestを用いた単体テスト。各機能に対して正常系・境界値・エッジケースのテストを記述。特にシード値の決定性（同一シード・同一操作で常に同一結果）を検証するテストを必須とする。
